# 文件用途、使用场景与操作命令

本页按文件查操作；从采集到训练的执行顺序见[总流程](../../README.md)。命令框需要整段复制，包括开头的 `cd`。终端提示符中的 `~` 表示家目录，不是项目目录。

| 运行位置 | 所在电脑 | 工作目录 / 解释器 |
|---|---|---|
| 本地 | 保存W_pro、连接相机和USB-CAN的电脑 | `/home/user/W_pro`；`.venv/bin/python` |
| 服务器 | `clwu@218.192.172.137` | `/home/clwu/vla-wu`；`vendor/openpi/.venv/bin/python` |

一条检查命令由“Python解释器 + 脚本 + 数据目录参数”组成。数据目录不是程序，不能放在 `.venv/bin/` 后直接执行。如果 `cd` 提示目录不存在，应先切回存有该项目的电脑，或使用项目实际路径。

## 一、采集脚本

### `scripts/acquisition/record_nero_demo.py`

**用途：** 临时录制三路RGB、左右CAN和参考快照，保存元数据与接收统计。

**什么时候用：** 需要新录一条红色示教时；已有记录不需要重新运行。运行前核实相机角色、CAN接口及从臂反馈来源。

**本地命令：**

```bash
cd /home/user/W_pro && \
.venv/bin/python scripts/acquisition/record_nero_demo.py \
  --output data/nero_demos/red --camera-fps 15 \
  --prompt '用右臂将红色物体放入透明盒子，然后双臂协作合上盒盖。' \
  --feedback-source-confirmed \
  --feedback-source-note '两主臂反馈推送关闭，两从臂开启；已对照从臂上位机核实关节反馈'
```

**结果：** `S` 开始；`F` 成功保存为 `data/nero_demos/red/episode_日期_时间/`；`X` 失败丢弃；Esc、关窗、Ctrl+C、计时结束或程序报错时丢弃本轮临时数据。成功保存前等待写入线程关闭。反馈来源参数应与现场实际核对一致。

需要录黄色任务时，同时改为 `--output data/nero_demos/yellow` 和黄色任务文本。设备操作见[采集说明](../acquisition/采集操作.md)。

仅观察设备接收情况，不保留试录数据：

```bash
cd /home/user/W_pro && \
.venv/bin/python scripts/acquisition/record_nero_demo.py \
  --output /tmp/nero_diagnostics --headless --seconds 10 --camera-fps 15
```

### `scripts/acquisition/nero_teleop_read.py`

**用途：** 只读监听当前左can1、右can0的关节目标、关节反馈、夹爪目标/反馈及控制状态，并核对USB-CAN序列号。

**什么时候用：** 采集前检查是否收到两侧反馈；主从夹爪不对应时，比较 `grip_target` 与 `grip_feedback`；接口重插后核对左右身份。

```bash

```

**结果：** 在终端显示接收数值、单位、新鲜度和计数，不生成数据文件，不发送控制指令。共享总线上的物理反馈来源仍需现场核实。

### `scripts/acquisition/test_three_cameras.py`

**用途：** 启动厂商RealSense Viewer。

**什么时候用：** 采集前检查基座、左腕、右腕画面和RGB设置，或排查相机是否被其他程序占用。

```bash
cd /home/user/W_pro && \

```

**结果：** 打开Viewer，需要手动开启三路RGB；结束后关闭Viewer再录制。只检查Viewer是否已安装：

```bash

```

## 二、数据脚本

### `scripts/data/check_nero_demo.py`

**用途：** 检查一条已保存原始记录的图像、CAN、参考快照和接收时序。

**什么时候用：** 想查看一条示教是否缺文件、缺关键报文、图像更新过慢或录制期间接收溢出时。它不判断画面中的任务是否真的成功。

```bash

  data/nero_demos/red/episode_20261117_154334_742573
```

**结果：** 终端输出图像帧率、CAN计数、快照情况、任务和问题列表，不改数据。检查其他示教时替换最后一个参数。

也可使用绝对路径，在任意工作目录运行同一条检查：

```bash
cd /home/user/W_pro && \
/home/user/W_pro/.venv/bin/python \
  /home/user/W_pro/scripts/data/check_nero_demo.py \
  /home/user/W_pro/data/nero_demos/red/episode_20261117_154334_742573
```

### `scripts/data/prepare_nero_dataset.py`

**用途：** 将一批原始成功示教按15 Hz对齐，生成16维状态、绝对目标、图像索引，并按整条示教划分训练/验证。

**什么时候用：** 首次处理一批采集数据，或新增示教后创建新数据版本。不是每次训练都要重做。

本轮 `nero_aligned_red_v1` 已存在。新增数据后生成一个尚不存在的v2目录：

```bash
cd /home/user/W_pro && \
.venv/bin/python scripts/data/prepare_nero_dataset.py \
  --input data/nero_demos/red --output data/nero_aligned_red_v2 \
  --validation-count 10 --seed 42
```

**结果：** 新目录中的 `dataset_manifest.json`、`split.json` 和各条示教的 `aligned.npz`、`alignment_report.json`。输出已存在时拒绝覆盖。历史失败记录保留但被排除；成功标签记录若有采集错误或中间流过期则报错停止。

`--validation-count` 是完整验证示教数；省略时约为成功示教数的20%。使用v2后，后续导出和模型批次也应改用v2。

## 三、模型脚本

### `scripts/model/nero_batch.py`

**用途：** 为新命名批次统一提供 `prepare`、`train`、`evaluate`；按导出报告读取条数和帧数，不固定为黄色8/2批次。

**什么时候用：** 当前红色新批次，以及以后使用新版本名的数据。运行位置均为服务器。

导出完成后，首次生成训练集统计：

```bash
cd /home/clwu/vla-wu && \
env -u LD_LIBRARY_PATH -u LD_PRELOAD JAX_PLATFORMS=cpu \
  vendor/openpi/.venv/bin/python -u scripts/model/nero_batch.py prepare \
  --project /home/clwu/vla-wu --dataset red_v1
```

统计已准备好、需要从官方pi0_base启动新微调实验时：

```bash
cd /home/clwu/vla-wu && \
env -u LD_LIBRARY_PATH -u LD_PRELOAD \
  CUDA_VISIBLE_DEVICES=1 JAX_PLATFORMS=cuda XLA_PYTHON_CLIENT_PREALLOCATE=false \
  vendor/openpi/.venv/bin/python -u scripts/model/nero_batch.py train \
  --project /home/clwu/vla-wu --dataset red_v1 \
  --exp-name "red_1000_$(date +%Y%m%d_%H%M%S)" --steps 1000 --save-interval 250
```

训练后需要验证集预测时，输入真实检查点路径：

```bash
cd /home/clwu/vla-wu && \
read -r -p '红色检查点完整路径，末尾为数字编号：' NERO_CHECKPOINT && \
env -u LD_LIBRARY_PATH -u LD_PRELOAD \
  CUDA_VISIBLE_DEVICES=1 JAX_PLATFORMS=cuda XLA_PYTHON_CLIENT_PREALLOCATE=false \
  vendor/openpi/.venv/bin/python -u scripts/model/nero_batch.py evaluate \
  --project /home/clwu/vla-wu --dataset red_v1 \
  --checkpoint "$NERO_CHECKPOINT" --all-frames
```

**结果：**

| 模式 | 输入 | 输出 |
|---|---|---|
| `prepare` | `data/nero_lerobot_red_v1/` 的训练集及导出报告 | `assets/pi0_nero_red_v1/local/nero_red_v1_train/` 的统计与来源报告 |
| `train` | 训练集、该批次统计、官方pi0_base参数 | `checkpoints/pi0_nero_red_v1/实验名/` 及 `results/pi0_nero_red_v1/train_*/` |
| `evaluate` | 本批次检查点、验证集 | `results/pi0_nero_red_v1/evaluation_*/` 中的预测NPZ与报告 |

示例使用GPU 1，应按现场空闲卡选择。1,000步最终检查点编号为999。省略 `--all-frames` 时每条验证示教只取开始、中间、末尾。新版数据需同步修改 `--dataset` 与导出repo，例如 `red_v2` 对应 `local/nero_red_v2`。

### `scripts/model/nero_pi0_adapter.py`

**用途：** 三相机角色映射、RGB布局/类型处理、16维状态/动作检查，以及将模型输出裁回16维。

**什么时候用：** 训练、统计和评估自动使用；只有更改相机角色、数据布局或机器人通道定义时才需要修改此文件。

**调用方式：** 公共模块，没有独立运行命令。由 `nero_pi0_config.py` 中的数据变换调用，再由 `nero_batch.py` 或黄色旧入口使用。修改后可在本地运行对应变换测试：

```bash
cd /home/user/W_pro && \

```

**结果：** 正常运行时输出变换后的数组，不单独写文件。变换改变后应为新数据版本重新准备统计。

### `scripts/model/nero_pi0_config.py`

**用途：** 定义pi0_base权重起点、LoRA、模型32维、动作块50步及NERO训练变换：14关节相对当前状态、两夹爪保持绝对宽度。

**什么时候用：** 模型工具自动读取。需要调整模型/数据变换基础设置时阅读；新批次名称、训练步数等优先使用 `nero_batch.py` 参数。

**调用方式：** 配置模块，无独立CLI。`nero_batch.py train` 和旧 `run_nero_pi0.py train` 调用 `get_train_config()`；新入口在运行时替换名称和repo。

**结果：** 返回训练配置，不执行训练或写检查点。黄色旧统计记录绑定其原版本，改动后需使用新版本流程。

## 四、旧独立接线的硬件维护

### `scripts/maintenance/nero_clear_estop_left.py`

**用途：** 左侧软件急停诊断与恢复。

**什么时候用：** 旧独立左臂确认为单纯软件急停，需要按现场流程恢复时；其他故障不由此脚本自动清除。

|---|---|---|---|
| `requirements.txt` | 本地采集/转换依赖，SDK从 `./pyAgxArm` 安装 | 新建本地环境，或本地依赖缺失 | 下方本地安装命令；不装进服务器OpenPI环境 |
| `.gitignore` | 排除环境、缓存和本地原始/派生数据 | 新增数据目录或排查文件为何未加入Git时 | Git自动读取，无独立运行命令 |
| `.gitmodules` | SDK子模块地址 | 新克隆项目、SDK目录未获取时 | 下方子模块命令 |
| `.vscode/settings.json` | 编辑器Python解释器和模块搜索路径 | 编辑器选错Python或提示导入找不到时 | VS Code打开项目自动使用；不是终端程序 |

已有项目、尚无本地环境时安装：

```bash
cd /home/user/W_pro && \
python3 -m venv .venv && \
.venv/bin/python -m pip install -r requirements.txt
```

Git克隆后获取SDK子模块：

```bash
cd /home/user/W_pro && \
git submodule update --init --recursive
```

### 备份和工具包文件

| 文件 | 用途 | 什么时候使用 | 命令/调用 |
|---|---|---|---|
| `data/archive/manifest.json` | 完整数据分卷顺序、大小、范围与校验信息 | 恢复或检查快照 | 由 `restore_github_data.py` 自动读取，不手工改 |
| `data/archive/nero-data.tar.gz.part*` | 同一完整无损压缩包的连续分卷，数量以manifest为准 | 缺失原始或对齐数据、需要恢复时 | 使用恢复脚本，不单独执行分卷 |
| `packages/nero-training-tools.tar.gz` | 服务器模型/导出/维护代码及说明 | 本地更新后同步到服务器 | 下方传输与解压命令 |

传输工具包（本地）：

```bash
cd /home/user/W_pro && \
scp packages/nero-training-tools.tar.gz clwu@218.192.172.137:/home/clwu/vla-wu/
```

解压安装（服务器）：

```bash
cd /home/clwu/vla-wu && \
tar -xzf nero-training-tools.tar.gz && \
python3 scripts/tools/organize_vla_wu.py --project /home/clwu/vla-wu --write-index
```

更新代码后重建工具包使用 [packages/README.md](../../packages/README.md) 的完整命令。工具包不含示教、权重和环境；原始数据传输命令见总流程。

### 第三方SDK与虚拟环境

`pyAgxArm/` 保存厂商SDK源码和文档。机械臂、夹爪接口分别查 [NERO API](../../pyAgxArm/docs/nero/nero_api.md)、[夹爪API](../../pyAgxArm/docs/effector/agx_gripper/agx_gripper_api.md)，SDK目录结构见其 [README](../../pyAgxArm/README.md)。项目维护入口调用其中接口；厂商演示脚本不作为当前主从共线采集的默认启动程序。

`.venv/bin/python` 是本地解释器，`.venv/lib/...` 是安装的依赖，供项目命令调用。无需逐个运行或修改依赖内部文件；缺少库时用上述requirements安装命令处理。
