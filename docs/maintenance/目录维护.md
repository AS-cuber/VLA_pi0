# 目录维护

## 本地 W_pro

`scripts/` 按采集、数据、模型、硬件维护和项目工具分目录，`tests/` 对应分组。文件用途和入口见[文件索引](文件索引.md)。模型目录中供服务器使用的文件在本地保留一份来源。

原始示教及对齐数据继续位于 `data/nero_demos/`、`data/nero_aligned_v1/`。厂商 SDK 和本地环境分别位于 `pyAgxArm/`、`.venv/`。

## 服务器 vla-wu

服务器整理包为 `packages/vla-wu-layout.tar.gz`。它将根目录的 NERO 模型脚本移到 `scripts/model/`，安装项目说明和维护工具；数据、统计、模型权重、正式结果、OpenPI 和运行环境保持原路径。

清理范围：

- Python 缓存；
- 没有有效检查点或有效子结果的失败运行目录；
- 已被完整对照替代的首次加载试跑和 6 帧抽样结果；
- 已完成任务的一次性 smoke 脚本和输出；
- 文件内容全部与展开目录一致的原始迁移压缩包。

正式训练日志、完整对照结果、可加载的检查点和原始示教保留。用途不明的额外文件保留原位并列出。

## 传输和执行

在本地采集电脑执行：

```bash
scp /home/user/W_pro/packages/vla-wu-layout.tar.gz \
    clwu@218.192.172.137:/home/clwu/vla-wu/
```

在服务器执行：

```bash
layout_dir=$(mktemp -d /tmp/vla-wu-layout.XXXXXX)
tar -xzf /home/clwu/vla-wu/vla-wu-layout.tar.gz -C "$layout_dir"
python3 "$layout_dir/organize_vla_wu.py" --project /home/clwu/vla-wu --apply && rm -rf "$layout_dir"
```

只查看操作清单时省略 `--apply`。模型进程仍在运行或目标位置已存在不同文件时，工具停止并提示。

整理后的入口：

```bash
cd /home/clwu/vla-wu
vendor/openpi/.venv/bin/python scripts/model/run_nero_pi0.py --help
vendor/openpi/.venv/bin/python scripts/model/check_nero_checkpoint.py --help
```

服务器 `README.md` 为入口说明，`docs/文件索引.md` 根据实际脚本生成。目录移动清单及被更新文档的原件保存在 `logs/maintenance/layout_*/`。整理工具安装在 `scripts/tools/organize_vla_wu.py`，可重复运行。

## 日常增加文件

采集代码放 `scripts/acquisition/`；转换代码放 `scripts/data/`；模型代码放 `scripts/model/`；说明写入对应 `docs/` 分类。每次实验使用独立名称，模型和结果由运行入口保存到服务器既定目录。

缓存和临时输出不放项目根目录。原始数据和有效模型不使用批量清理命令删除。
