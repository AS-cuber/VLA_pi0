## 官方资源与模型选择

- [NERO 使用资料](https://agilexsupport.yuque.com/staff-hso6mo/alxgtf/hf8x32y0tevqyi3g?singleDoc#)：提供 SDK、URDF、MuJoCo 和零点校准入口。
- [官方 NERO MuJoCo 目录](https://github.com/agilexrobotics/agx_arm_sim/tree/master/mujoco/agilex_arm/agilex_nero)：含 XML 和网格资源。
- [MuJoCo Python 安装与 Viewer](https://mujoco.readthedocs.io/en/stable/python.html)：提供 `mujoco` 包和 `python -m mujoco.viewer --mjcf=...` 入口。

本次查看的仿真仓库版本：`f8cd8b147c75d59e14f90fb0646770eefa268ed0`。其中：

| 文件 | 内容 |
|---|---|
| `scene.xml` | 地面、灯光和单臂场景，包含 `nero.xml` |
| `nero.xml` | 七关节 NERO、双指夹爪、位置执行器与关节限位 |
| `scene_nero_arm.xml` | 包含 `nero_arm.xml` 的另一单臂场景 |
| `nero_arm.xml` | 与 `nero.xml` 的部分关节限位和阻尼不同，并非可直接互换 |
| `assets/` | 机械臂与夹爪网格，XML 加载时需要 |

例如该版本 `nero.xml` 的 J2 范围为约 ±1.74 rad，而 `nero_arm.xml` 为约 -0.262～3.316 rad。本地 SDK 的 NERO 默认 J2 范围约 ±1.745 rad，因此先以 `scene.xml` 为查看入口；最终仍以现场固件、安装方式和校准后的反馈核对零位、正方向与限位。不要为了让轨迹播放而直接放宽限位。

## 9. 双臂与动作预览（待实现）

**启动命令：当前尚无双臂播放器入口，待实现后补充。步骤 3 的单臂 Viewer 命令不能替代这一步。**

在本地增加双臂场景和播放器。自编代码放 `scripts/simulation/`，场景与安装参数放 `configs/simulation/`，回放视频放 `results/simulation/`；这些目录在实现相应功能时创建。厂商资源保持在 `vendor/`。

双臂场景需要给两套模型的关节、执行器等命名加左右前缀，并按实测安装位姿放置。先摆放双臂与桌面即可；盒子、物体和合盖接触模型不必成为动作预览的前置工作。检查相碰时，双臂底座相对位置和桌面高度必须与现场一致。

动作接口固定为：

```text
[左 J1..J7, 左夹爪宽度, 右 J1..J7, 右夹爪宽度]
关节：rad；夹爪总开口：m
```

按名字找到每个关节的 `qpos` 地址和执行器，不能把 16 维向量直接拷进 MuJoCo 的 `qpos`：官方单臂 XML 有七个转动关节、两个手指滑动关节，只有八个执行器。其手指约束为 `gripper_joint2 = -gripper_joint1`；总开口需要转换为指关节位移，并用闭合、半开、全开三种姿态确认网格指面间距和方向，不能把总宽度直接作为单指位置。

先回放一条完整示教的 `aligned.npz` 中的实测状态，核对零位、方向和开合。随后查看模型动作，可直接使用此前 1,000 步全验证集评估保存的文件，无需再次计算误差：

```text
服务器 /home/clwu/vla-wu/results/pi0_nero_box_v1/comparison_*/trained/
  report.json                 检查点来源及各帧所属示教
  validation_actions.npz      predictions / references / states / valid_mask / dataset_indices
```

选择 `report.json` 中 `trained_checkpoint` 对应 1,000 步模型、且范围为 `all_validation_frames` 的那一组；不要把 100 步结果混入。复制所选 NPZ 与报告到本地同一预览目录，使用其中 `anchors` 信息分开两条示教。

可以从某个 `states[i]` 出发预览 `predictions[i, :K]`，也可按原示教时刻显示每次预测的第一步目标。后者使用了记录中的后续观测，不是模型自主完成任务。不要把连续帧的 50 步预测块首尾相接，动作窗口彼此重叠。

第一版用设置关节位置、调用 `mj_forward` 的方式查看姿态和路径；这不验证力矩或抓取接触。需要检查执行器跟随和接触时，再向 `data.ctrl` 写目标、调用 `mj_step` 推进物理仿真。

## 11. 实机短段执行（待实现）

**启动命令：当前尚无自主执行入口，待实现并核对当前总线接线后补充。现有使能、失能脚本不能替代自主执行器。**

先实现本地从臂执行接口：读取状态、写绝对关节/夹爪目标、检查限位和每次目标变化、控制速度、处理观测过期和通信超时，并支持操作员停止。异常时的停止或保持行为应按实际 SDK 控制模式确定，不继续执行缓存动作。

当前采集接线为左 `can1`、右 `can0` 的主从共用总线。自主运行前停止主臂发送目标并明确电脑控制权。现有维护脚本采用旧独立 USB-CAN 映射，不能直接作为当前接线的模型执行器。控制模式、固件和限位依据本地 [NERO API](../../pyAgxArm/docs/nero/nero_api.md) 及 [夹爪 API](../../pyAgxArm/docs/effector/agx_gripper/agx_gripper_api.md) 接入。

先在无接触、远离桌面和双臂互碰的位置执行一个短动作段，核对左右顺序、方向与夹爪；确认可停止后恢复示教起始布置，进行右臂入盒、双臂合盖。操作员全程在场。

模型动作间隔沿用训练数据的 1/15 秒；50 步对应约 3.33 秒的预测跨度，不等于一次下发并盲执行整段。首次接入执行少量动作点后重新观测，根据实测推理与通信延迟确定执行长度、插值和刷新节奏；底层控制发送频率另按所选 SDK 模式确定。

完整闭环：

```text
本地三相机 RGB + 从臂实测状态
  → 服务器候选模型推理
  → 本地检查和执行短动作段
```
